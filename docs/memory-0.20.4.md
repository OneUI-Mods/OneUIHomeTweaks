# 0.20.4 メモリ保持の修正

## 問題と変更

ホーム文字色のSavedはWeakHashMapの値だが、完了済みValueAnimatorを保持し、その更新コールバックがキーのTextViewを強参照していた。この経路では弱いキーだけにしてもViewが回収されない。アニメーションの対象をWeakReferenceへ替え、正常終了・中断の両方で更新リスナーと終了リスナーを外し、同じアニメーターならSavedからも除く。

フェードの120ms、配色の判定、キャンセル後の最終色、別の所有者へ移ったViewの色を維持する。描画頻度・背景採取のタイミングを削る変更はしていない。完了済みアニメーターを残したまま弱いキーのViewを保持できる経路を切る修正で、任意のホームActivityを強制破棄する機能ではない。

## 検証

- 既存JVMテスト165件、releaseビルド、lintが成功。
- Android 16/17のCOWエミュレーターで本物のTextViewとValueAnimatorを使用。正常終了・中断後の最終色、Savedからの除去、終了リスナー解除を確認した。
- 完了後にアニメーターを外部から動かしても、別途設定したViewの色が変わらないことを確認。
- 所有者をマップから外した後のcancelが新しい色を上書きしないことを確認。
- アニメーターとキャッシュ自体を保持したままTextViewの弱参照がGCで空になり、WeakHashMapのエントリーが消えることを確認。GC要求は仮想端末のテスト専用で、製品・Galaxy・SystemUIへGC要求を追加していない。

エミュレーターの試験はフックやOne UIホームを起動せず、検証専用Activityを製品へ追加していない。長時間の実機削減量は未測定。アプリ更新後、既に動いているOne UIホームへ反映するには対象だけの再読み込みが必要。

## 別途残る調査

実機の短いトレースで、ホーム文字色のワーカーからsystem_server.screenshotWallpaperへ49回の呼び出しを確認した。合計の壁時計時間は約719ms。全解像度の取得後に縮小する経路であるが、Bitmapはfinallyでrecycleされており、これだけで恒久的な画像リークとは主張しない。ライブ壁紙の追従を落とさず、取得時の一時メモリを減らす案は別の検証が必要。
