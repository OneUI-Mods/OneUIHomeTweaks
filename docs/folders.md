# フォルダからのアプリ起動と復帰

## 設定

`folder_return` は既定でON。モジュール全体またはホームの変更がOFFなら、設定値にかかわらず純正動作を維持する。既存のフォルダ・アプリ配置・ランチャーのデータベースは書き換えない。

ONでは純正のフォルダへのジェスチャー復帰を維持。OFFでは、閉じる先の解決前に純正の通常状態へ戻して、閉じたフォルダをターゲットにする。フォルダの閉じ動作は、起動元や過去のアプリ復帰記録に依存せず、位置だけで再利用される縮尺キャッシュを純正APIで破棄し、最新のレイアウトから作り直す。復帰後、既にフォーカスがあるホームへのHOME Intentだけは、即時の状態変更を純正350msの状態変更へ渡す。アプリから復帰する最初のHOME Intentや設定変更・画面回転を一律アニメーション化しない。

## 独立した契約

| APK | manager | animator | prepare / geometry reset | VM field / manager getter |
| --- | --- | --- | --- | --- |
| Android 16 / AZHL | g3.i | K5.p1 | t(JZ)V / c()V | f / Y() |
| Android 17 / BZI9 | t5.h | lb.e0 | A(JZ)V / k()V | c / y0() |

双方のAPKをDEXで照合し、引数と戻り値を確認した。推測による16へのフォールバックは行わない。登録前に必要メソッドをすべて解決し、登録中の失敗はロールバックする。実行中の例外はフォルダ機能だけを停止する。

## 検証記録（2026-10-22）

修正前のAndroid 17実機でカメラアシスタントをフォルダから起動し、上スワイプでフォルダへ戻ることを確認。Homeキーコマンドはフォルダを閉じる別経路なので検証に代用しない。外側タップでは純正の閉じアニメーションが記録されており、ユーザー報告の全経路で消失を再現したとは扱わない。修正後の署名済みrelease版（0.16.0 / code 26）を上書きして、One UIホームだけを再読み込みした。Vectorがbuild 26を読み込んだこと、フォルダ処理の登録、ONでフォルダ内へ戻ること、OFFで閉じたフォルダのホームへ戻ること、再読み込みせずONへ戻せることを確認した。復帰後の二度目の上スワイプでは、録画を20fpsで抽出し、フォルダが段階的に縮小してアイコンへ戻る純正アニメーションを確認した。フォルダ設定は既定のONへ戻した。ホームの終了理由はINTENTIONAL、healthy=true、attempts=0、blocked=false。SystemUIやAndroid本体は今回の確認で再起動していない。途中キャンセルや全てのHome Up構成について確認済みとは扱わない。Android 16はソースとDEXの照合であり実機再試験は未実施。

## 通知経由・繰り返しの閉じ操作（0.20.1）

従来は`findCloseAnimationTarget`がフォルダの開いている状態で呼ばれた時だけ、managerを一時記録していた。閉じ準備でこの記録を消す一方、フォーカス済みHOME Intentの即時遷移をアニメーションへ渡す条件にも同じ記録を使っていた。通知起動などでターゲット探索を通らない場合と、前の閉じ準備が記録を消した場合に、修復対象から外れる実装上の欠落を確認した。

修正では一時記録を廃止した。閉じる側のフォルダ準備だけで純正のgeometryを更新し、HOME Intentの修復は「機能ON・フォルダ復帰ON・実行中の自己呼出しでない・既にフォーカスがあるHOME Intentの内側・開いているフォルダ・通常ホームが遷移先」で限定する。初回のアプリ復帰、通常の即時リセット、無効時、フォルダを開く側は変更しない。復帰先を新しくフォルダへ強制する処理は追加していない。通知の文面・送信元やIntent extrasを保存しない。`FOLDER_CLOSE`には閉じ準備の所要時間引数と経路・カウンタだけを記録する。

純正Animatorには別途、実際の重なりによる非アニメーション化と、座標が原点の時の即時終了分岐が存在する。この修正はその判定を一律無効にしない。実機で原因が異なる場合は、修復経路のログと純正ログで区別する。Android 16/17の既存の個別契約とキャッシュ方式は維持する。
