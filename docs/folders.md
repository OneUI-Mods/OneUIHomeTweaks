# フォルダからのアプリ起動と復帰

## 設定

`folder_return` は既定でON。モジュール全体またはホームの変更がOFFなら、設定値にかかわらず純正動作を維持する。既存のフォルダ・アプリ配置・ランチャーのデータベースは書き換えない。

ONでは純正のフォルダへのジェスチャー復帰を維持。OFFでは、閉じる先の解決前に純正の通常状態へ戻して、閉じたフォルダをターゲットにする。フォルダの閉じ動作は、起動元や過去のアプリ復帰記録に依存せず、位置だけで再利用される縮尺キャッシュを純正APIで破棄し、最新のレイアウトから作り直す。復帰後、既にフォーカスがあるホームへのHOME Intentだけは、即時の状態変更を純正350msの状態変更へ渡す。アプリから復帰する最初のHOME Intentや設定変更・画面回転を一律アニメーション化しない。

## 独立した契約

| APK | manager | animator | prepare / geometry reset | VM field / manager getter |
| --- | --- | --- | --- | --- |
| Android 16 / AZHL | g3.i | K5.p1 | t(JZ)V / c()V | f / Y() |
| Android 17 / BZI9 | t5.h | lb.e0 | A(JZ)V / k()V | c / y0() |

双方のAPKをDEXで照合し、引数と戻り値を確認した。推測による16へのフォールバックは行わない。登録前に必要メソッドをすべて解決し、登録中の失敗はロールバックする。実行中の例外はフォルダ機能だけを停止する。

## 検証記録（2026-10-22）

修正前のAndroid 17実機でカメラアシスタントをフォルダから起動し、上スワイプでフォルダへ戻ることを確認。Homeキーコマンドはフォルダを閉じる別経路なので検証に代用しない。外側タップでは純正の閉じアニメーションが記録されており、ユーザー報告の全経路で消失を再現したとは扱わない。修正後の署名済みrelease版（0.16.0 / code 26）を上書きして、One UIホームだけを再読み込みした。Vectorがbuild 26を読み込んだこと、フォルダ処理の登録、ONでフォルダ内へ戻ること、OFFで閉じたフォルダのホームへ戻ること、再読み込みせずONへ戻せることを確認した。復帰後の二度目の上スワイプでは、録画を20fpsで抽出し、フォルダが段階的に縮小してアイコンへ戻る純正アニメーションを確認した。フォルダ設定は既定のONへ戻した。ホームの終了理由はINTENTIONAL、healthy=true、attempts=0、blocked=false。SystemUIやAndroid本体は今回の確認で再起動していない。途中キャンセルや全てのHome Up構成について確認済みとは扱わない。Android 16はソースとDEXの照合であり実機再試験は未実施。

## 通知経由・繰り返しの閉じ操作（0.20.1）

従来は`findCloseAnimationTarget`がフォルダの開いている状態で呼ばれた時だけ、managerを一時記録していた。閉じ準備でこの記録を消す一方、フォーカス済みHOME Intentの即時遷移をアニメーションへ渡す条件にも同じ記録を使っていた。通知起動などでターゲット探索を通らない場合と、前の閉じ準備が記録を消した場合に、修復対象から外れる実装上の欠落を確認した。

修正では一時記録を廃止した。閉じる側のフォルダ準備だけで純正のgeometryを更新し、HOME Intentの修復は「機能ON・フォルダ復帰ON・実行中の自己呼出しでない・既にフォーカスがあるHOME Intentの内側・開いているフォルダ・通常ホームが遷移先」で限定する。初回のアプリ復帰、通常の即時リセット、無効時、フォルダを開く側は変更しない。復帰先を新しくフォルダへ強制する処理は追加していない。通知の文面・送信元やIntent extrasを保存しない。`FOLDER_CLOSE`には閉じ準備の所要時間引数と経路・カウンタだけを記録する。

純正Animatorには別途、実際の重なりによる非アニメーション化と、座標が原点の時の即時終了分岐が存在する。この修正はその判定を一律無効にしない。実機で原因が異なる場合は、修復経路のログと純正ログで区別する。Android 16/17の既存の個別契約とキャッシュ方式は維持する。

## 追加の実機確認（2026-11-03）

通知起動で渡る一時managerの有無とは無関係に、未起動のフォルダ開閉と外部Activityからの復帰を実機で確認した。4回の閉じ準備でgeometryの再生成と純正350ms処理の開始・終了を記録した。直近のLINE・Instagram通知は残っておらず、その通知PendingIntent経由そのものを再現済みとは扱わない。HOMEキーのコマンドと上スワイプの確認は区別して保存している。通知起動時にフォルダが復帰先になるかどうかの純正ポリシーを一律に変える修正ではない。

初回更新時、Vectorが旧版モジュールを保持していたため、モジュールの無効→有効による登録再取得と対象ホームだけの再読み込みで実際のbuildを確認した。続いて発覚したhost JNI読込の失敗は、モジュール自身のAPK内のネイティブライブラリを選ぶ経路で解消した。OS・SystemUI・認証設定の再起動／変更は行っていない。設定のXMLは元と一致した。

最終検証では、調査用の直接起動がstandardのLauncherActivityを追加していたことを確認して除去した。修正後は通常のHOMEタスクでページ0→1→0の壁紙エンジン入力（step=1/3）と、フォルダの350ms閉じ準備を確認した。シェルで直接作ったホーム画面だけの検証では完了としない。

## 内部HOMEキー通知と高速フリック（0.20.2）

再現条件は「フォルダを開く→中のアプリを起動→上スワイプでフォルダへ復帰→大きく速い上スワイプ」。ゆっくり閉じる場合や、アプリを開かずフォルダを閉じる場合と区別する。

Android 17 / BZI9の純正DEXでは、`jb.i.invokeSuspend`がaction/categoryのないIntentへ`android.intent.extra.FROM_HOME_KEY=true`を設定し、HoneySpaceUtilityへ直接渡す経路を確認した。実機ログでもextrasだけのIntentがOneUiSpaceへ届いている。この経路はLauncher Activityの`onNewIntent`を通らず、従来の動的スコープ外で`gotoScreen`が実行される。

Android 17の契約へ`HoneySpaceUIComponent.handleKeyPolicy(Intent): boolean`を追加し、このネイティブ処理の呼出し中にも閉じ要求のスコープを設定する。privateメソッドのAOTインライン対策として呼出し元`onNewIntent`をdeoptimizeする。内部通知にはaction/categoryがないため通常のHOME Intentであることを要求しない。HOMEキーextraと表示中のrootを必須とし、action/categoryがある通常の要求は従来どおりフォーカスも必要。action/categoryのない内部通知では、アプリから復帰中の一時的なフォーカス受け渡しを許容する。最初のアプリ復帰にはHOMEキーextraがないため対象外。実際の置換は従来と同じく、復帰設定ON・開いたフォルダ・通常ホームへの即時遷移に限り、純正350msアニメーションへ渡す。呼出し後には入れ子のスコープを復元し、Intentや履歴を持ち越さない。

Android 16の既存契約と解析プロファイルは変更しない。新しい所有クラスは17のDexKitプロファイルにメソッドの型・戻り値を記録し、初回／更新後のみの探索方式を維持する。

同じキー処理中に純正の閉じ準備がすでに行われた場合は、そのmanagerを呼出し単位で記録する。後続の即時`gotoScreen(Home.Normal)`が同一manager・すでに通常ホームへの遷移中なら、この重複要求だけを抑止して元のアニメーションを継続する。別managerや通常の状態初期化を抑止しない。

### 検証（2026-11-04）

署名済みrelease 0.20.2 / code 43を上書きし、One UIホームだけを通常のHOMEタスクで読み込み直した。新PIDの`MODULE_LOADED build=43`とフォルダフックの登録を確認し、ユーザーが報告した高速ジェスチャーで「なおった」と確認した。その操作中、新PIDのログには`focused_home nativeDuration=350`が3回、対応する閉じ準備も3回記録された。元のbuild 42には通常速度で350msの縮小があることを録画で確認している。修正後の高速操作の目視判定はユーザーによるもので、エージェントが操作・録画して確認したものではない。重複close抑止の分岐はJVM試験で検証し、今回の実機ログで通った経路は350msへの引き渡し側だった。

JVM 163件、releaseビルド・Lint・配布証明書・APK構造検証を通過。Android本体のboot ID、system_serverとSystemUIのPID、SELinux Enforcing、解除状態を維持した。追加の画面操作は行わず、消灯防止用の一時入力ループも停止した。Android 16は既存プロファイルの内容が不変であることを機械比較し、実機再試験は行っていない。
