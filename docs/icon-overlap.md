# Home icon overlap correction

The November 3 physical trace identified Home Up 18.0.00.36 `StickerOperator.hideOverlapStickers` as the caller setting a separate neighboring icon to alpha zero. The same view was restored after 824–827 ms, followed by the native 100 ms alpha/scale return. The closing target was the correct Settings home icon. This establishes the direct hide/restore path; it does not prove that every device or layout has the same trigger.

`IconOverlapHooks` observes the real FreeGrid workspace to obtain the plugin class loader. Android 16 and Android 17 have separately selected contracts. Their reviewed operator, bounds helper and `launchedView` field have the same names. Signature/return/field types are checked before interception, and the native caller is deoptimized so its intersection test cannot bypass interception through AOT inlining. Unknown contracts remain native.

Only a closing call to `StickerOperator.hideOverlapStickers(Rect, StickerContainer, List, int, boolean)` enables a thread-local scope. The scope is restored in `finally`, including native exceptions and nested calls; nested opening calls cannot inherit closing scope. Outside this scope, the intersection helper is untouched. Both views must implement `AnimatableIconView` and have the identical direct FreeGridCellLayout parent. Folder contents, drawer, widgets, stickers and unrelated callers are excluded.

A conservative second check maps each entire view rectangle through its own matrix and offsets it into its common parent's coordinates. This preserves per-icon rotation, scale and translation but excludes the moving common ancestor. Only provably disjoint, finite, nonempty bounds return false before the original intersection test. Bounding-box overlap (including labels), rotated ambiguity, absent views, zero dimensions and unknown types keep the native result. This does not change actual alpha, animations, elevation, layout parameters, database or Home Up preferences. It is not a global override of View visibility.

Default `icon_overlap_fix=true`; launcher master switches also apply. An OFF change removes correction immediately via the existing configuration observer. A contract or runtime error stops this feature without disabling the rest of Home Tweaks. No poller, draw listener, frame callback or resident service is added. The status includes a candidate-exclusion counter, with only the first five events logged.

JVM regression cases cover measured neighboring containers, intentional overlap/containment, label/rotated-bound ambiguity, both axes/order and unknown/singular geometry. Android 17 physical verification on SM-S948Q / BZI9 passed: ON kept the neighboring icon visible throughout return; OFF reproduced the native disappearance for 828 ms; restoring ON removed it again, without reloading between changes. The counter counts excluded candidate tests, not necessarily native true intersections. The setting was toggled through the actual app switch, and existing preferences were restored; the sole retained addition is the enabled new option. Only the Launcher process was reloaded for initial installation; boot ID, system_server, SystemUI and SELinux were unchanged. The original foreground home screen was restored. All 146 JVM tests and release lint passed. Android 16 has source-contract coverage and retains native behavior if that contract cannot be resolved; no Android 16 physical verification is claimed for this update.
